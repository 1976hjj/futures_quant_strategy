# 数据准备与报告交付清单

日期：2026-09-13。当前仅完成文档和代码关键词核查，未证明数据可用，未运行策略。

## 1. 最先需要找到的既定定义

需要补充已经确定的5维 Risk Score原文或项目内路径。不能用“五维”这个名称推断维度组成，也不默认等权。

| 定义项 | 需要的内容 |
| --- | --- |
| 每一维 | 名称、金融含义、明确公式、风险方向 |
| 输入 | 数据域、指数/全市场/历史成分范围、字段和单位 |
| 时间 | 回看窗口、最低有效数量、发布延迟、available_at |
| 映射 | 各维到分数的转换、0和100的含义、极端值规则 |
| 合成 | 权重、合成公式、最终0–100映射 |
| 异常 | 缺失、停更、分母为0、超范围、历史修订处理 |
| 版本 | 定义日期、已有测试记录、使用过哪些历史区间 |

如果某维涉及市场宽度或成分估值，需要历史时点成分及可用时间；这属于评分输入，不是选股策略。不能用今天成分回填过去。若原定义没有这些维度，则不额外引入。

## 2. 数据审计计划

1. 先读元数据和访问规则，明确可读取区间，避开未释放holdout。
2. 核对三指数正式身份、收益口径、发布日、回溯区间和供应商版本。
3. 核对日历、OHLC、收益连续性、单位、重复行和缺失；不以向前填充制造可交易行情。
4. 按五维公式逐项检查历史覆盖和可用时间，区分回看预热不足与中途断档。
5. 确认是否存在原始指数序列、全收益序列及必要的历史成分；个股行情仓库不能自动替代这些数据。
6. 输出共同有效区间与各指数有效区间，再冻结样本切分、成本及协议版本。

证据应记录数据源、快照/文件哈希、抓取时间、业务日期、可用时间、发布前回溯标记、质量结论及受影响区间。不得覆盖现有原始数据、研究宪法、历史实验或暴露账本。

## 3. 后续正式运行的交付结构

建议每次运行追加到 `risk/runs/<run_id>/`，当前不创建空结果或填造绩效。

| 文件 | 内容 |
| --- | --- |
| experiment_spec.json | 五维版本、六策略规则、样本边界、成本、统计协议 |
| data_audit.json | 数据快照、覆盖、质量问题、访问范围 |
| daily_evidence.csv | 日期、指数、五维分数、总分、信号时间、目标仓位、实际仓位、现金、净值、费用、回撤 |
| trades.csv | 交易时点、前后持仓、成交假设、名义交易量和费用 |
| comparison.csv | 每个评价样本3指数×6策略=18行，全部核心指标 |
| annual_returns.csv | 完整年收益及单独标记的残年收益 |
| stress_events.csv | 所有预登记/机械事件、减仓滞后、反弹损失、Risk Flip |
| robustness.csv | 成本、样本外、B1-PIT、配对差区间等附加结果 |
| nav.png / drawdown.png | 三指数各一面板、每面板六条曲线、统一策略配色 |
| exposure.png | 仓位与Risk路径，解释风险下降来源 |
| report.md | 三个核心问题的逐指数结论、失败案例、限制 |
| manifest.json | 输入/输出哈希、运行标识、协议版本和生成时间 |

主图各面板从同一起始净值1出发，回撤使用各策略自身历史峰值；压力窗口图保留原账户路径。最长历史、共同区间、发布后和样本外结果分开展示。B1-PIT放附表，主表保留用户要求的18行。

## 4. 推进顺序

先补齐既定评分定义，然后审计数据并冻结协议，再进行独立计算及必要的时序/核算验证，最后从证据生成表格、净值图、回撤图和报告。计算脚本如需新增，也放在risk范围内；本阶段不开发页面或后端，不改Alpha/因子研究流程。

目前需要用户补充的信息只有既定5维公式或其所在位置。其余工程细节可按协议草案继续细化；实际样本日期由可用数据和既有样本暴露记录决定，不凭空指定。
