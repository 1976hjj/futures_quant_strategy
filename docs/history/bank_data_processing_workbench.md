# 银行分层处理接口记录

日常操作已改为[银行因子统一计算](../bank_factor_computation.md)。数据管理不再展示标准事实、派生处理卡片，
银行板块择时不再使用独立计算面板。下面保留旧分层流程及内部接口说明，供复现、核验和排查使用。

数据管理中的操作顺序为：原始归档 → 标准事实处理 → 派生数据处理。
银行板块指标计算位于“因子计算 → 银行板块择时”，读取选定的派生版本。
本流程只准备数据和研究指标，不生成仓位、收益标签或回测。

## 页面操作

1. 通用/行业更新负责拉取来源，原有仓库处理继续随更新执行。
2. 标准事实区选择“复现已冻结的研究来源”或“重新核验当前归档”，检查计划后处理已有数据。
   后者用于补采或修订后的重新整理；两种处理均不下载数据、不调用Token接口。
3. 派生区选择标准事实版本，检查计划后计算银行基础包。
   基础公式复用原选股流程，额外构建拨备/资本同报告期同比、含分红序列、滞后样本等权篮子和历史覆盖。
4. 查看数据缺口，按字段筛选并分页检查需补采或核验的银行。
5. 银行板块择时区选择派生版本和指标，检查计划后可手动计算。
   PB相关输入不足时输出空值和原因；不以0代表缺失。结果按日期分页，保留各分项。

每个处理任务保存请求、进度、输出版本和日志。来源更新与处理任务互斥；任务进程退出会显示失败。
上游、配置或计算代码改变后，过期的计划不能直接执行，需重新检查。

## 版本与研究范围

- 原始归档日期与研究处理日期分别展示。本轮已开放研究范围为2020-01-02至2025-12-31。
- 冻结来源用于复现旧研究，不自动追随最新采集；当前归档来源按研究切点重新核验。
- 未核验修订版本沿用保守可用时间，不能把新采集时点改成历史公告日。
- 标准事实、派生输入和板块结果各自保存独立不可变版本，并记录直接上游ID。
- 选择较晚起点时自动携带已开放的预热历史。派生包分别保存展示区间和历史上下文，不能从展示起点重新预热。
- 原选股发布、原始数据、PIT仓库、历史研究包均保留。
- 处理完成表示流程执行成功；字段缺口与历史披露/行业认证限制另行展示，不能视为正式认证通过。

## 历史和增量的当前实现

目前支持按上游版本检查：相同来源、日期、配置、指标选择和代码版本直接复用已有结果。
首次处理、日期扩展或历史来源修订时，以指定研究范围及必要预热历史重建并生成新版本。
这是一套可追溯的更新流程，尚未实现所有指标逐分区、仅重算受影响日期的细粒度增量引擎。
页面明确显示实际执行方式；不把范围重建标成仅追加一天。

## 接口与存储

接口位于数据管理服务的 `/api/v1/data/processing`：

- `GET /inventory`：日期边界、版本、就绪汇总。
- `POST /plan`：检查来源、范围、缓存和执行方式。
- `POST /jobs`：启动手动处理任务；绑定预检键和上游版本。
- `GET /jobs/latest`、`GET /jobs/<id>`：持久任务进度。
- `GET /gaps`、`GET /values`：带版本及字段/指标筛选的分页结果，页大小上限100。

标准事实与板块结果保存在 `data/bank_processing_store`，派生包沿用 `data/bank_timing_store/packs`。
发布完成清单最后写入；文件哈希校验失败时拒绝复用。辅助任务记录保存在 `reports/bank_processing`。
