# 完整数据更新操作与每周维护

更新顺序：通用来源 → 银行行业 → 官方财报原文核验 → 必要因子计算。
“刷新覆盖状态”只读取本地目录，不下载数据，不调用付费接口。

## 页面按钮

1. 打开“数据管理”，点击“刷新覆盖状态”。确认 Token 已配置，没有正在运行或排队的回测、来源更新或因子依赖准备任务。
2. 在“通用数据”勾选全部六项：证券名册与 PIT 状态、日行情与估值、财务披露、涨跌停价格、分红与送转、沪深 300 基准。
3. “更新至”选择页面允许的最新日期。当天行情在北京时间18点以后更新；并发2，磁盘下限10 GiB，请求间隔50 ms，刷新最近财报期4。
4. 点击“检查通用更新计划”，确认计划和凭证状态，点击“开始通用增量更新”。等待“最近一次更新”显示“已完成”，失败先查日志；失败任务不视为更新完成。
5. 在“行业数据”勾选“银行基本面、财务与估值”，设置相同截止日期，并发2，磁盘下限10 GiB。日常选“日常增量”，每周完整维护或新财报、分红公告、更正发布后选“完整检查”。点击“检查行业更新计划”→“开始行业增量同步”。等待完成。免费补充源随完整财务检查处理，不需要单独操作。
6. 点击“复制财报补充提示词”，发到当前项目对话。核对官方新季报、中报、年报、更正公告及分红事件，与已归档版本比较并补缺。本次对话任务只做原文补充与核验，不重复启动页面接口同步。源接口完成不能代替原始公告核验；未披露字段保留缺失，不能补零。
7. 打开“因子计算”，选择需更新的银行个股或板块指标，在已授权日期范围内预检并启动计算，查看覆盖和缺项。来源采集不自动重算因子，不自动重做图表或报告，不扩大研究范围。

通用“刷新最近财报期”大于0时，即使目标覆盖日期未变，也会实际执行财务复查；设置0才允许按已覆盖状态跳过。
银行行业更新不推进全市场覆盖日期；全市场行情更新也不替代银行专用原文证据核验。
沪深300通用基准与银行研究所需的沪深300全收益来源分别核验，不能以价格指数冒充全收益指数。

银行日常增量默认AUTO：每家只采集行情、复权系数及日估值三类接口；已有财务采集时间
不足7天时复用财务、分红和免费源，保留原采集时间及证据。首次采集、财务检查已满7天或
手动FULL时采集全部八类接口；FULL同时重新检查免费补充源。当前没有实时公告监控，
AUTO不能保证发现检查间隔内新发的财报、分红或更正，已知发布时应手动选择完整检查。
日常仍保存新的行情版本和整合版本，这不意味着重新下载全部历史。

重算财务输入会检查银行库各次已发布数据版本，按计算时点和来源规则选取当时可用值。
最新采集晚于历史计算日时，不使用该版本回填历史，而是选当时已经可用的版本。
修订、可用时间、单位和来源记录均保留；旧回测结果不覆盖。

### 银行更新进度

银行行业任务按八个阶段报告：读取已有归档、采集银行接口、合并接口历史、免费来源补充、
整合财务字段与检查冲突、核对字段来源、整理分红事件、入库并发布新版本。
接口采集显示完成任务数（当前42家、每家8类接口，共336个任务），分页及请求重试单独显示；
财务整合每50个字段记录更新一次，来源核对每50个报告期更新一次。页面显示当前处理对象、
阶段计数、已运行时长和距上次进展的时间。流程百分比按阶段工作计数加权，不预测剩余时间。
子步骤成功不能表示整项成功，最终发布成功且外层任务结束后才显示100%。失败保留失败阶段和计数。
旧任务未采集这些明细时保留原记录，不事后猜测进度；详细阶段信息从新版任务开始保存。
Windows子进程明确使用UTF-8日志，旧GBK日志按兼容编码读取。

## 台账与提醒

- 数据管理页展示各来源覆盖截止、最近成功采集时间及距今天数。时间依据已发布来源的采集元数据和实际执行成功的任务，不以文件修改时间冒充采集时间。
- 7天到期提示每周检查；30天提示久未更新，建议执行完整流程。这是距上次采集的时长，不代表用户是否登录或使用了页面。
- 当前浏览器额外记录上次打开数据管理的时间，间隔达到30天时提示久未使用后先检查台账；浏览器历史被清理或换浏览器时不推测使用间隔。
- 缺少可核实时间的旧归档显示“暂无成功时间记录”，不据此认定没有数据。
- 任务失败、无实际更新的成功任务不重置提醒时钟。分页历史保留成功、失败及无须采集的任务。
- 官方新报告是否已发布、已归档、已核验需要在对话工作中核实；当前台账不宣称已接入实时公告监控，也不宣称所有银行最新财报齐全。

点击“开启本页每周通知”后，由浏览器申请通知权限。每周一北京时间20:30提醒；错过后下次打开数据管理页补提醒，每个浏览器每周最多一次。
本页通知需要数据管理页保持打开；关闭页、应用或电脑后不运行。可点击同一按钮关闭；该设置只保存在当前浏览器。

不提供 ChatGPT 定时任务复制按钮。用户在页面手动更新接口数据，通过项目对话补充和核验原文财报。

## 对话更新提示词

完整文本由 `scripts/data_maintenance.py` 提供，页面可查看或复制。对话请求覆盖官方报告收集、证据和版本保留、指标口径、缺项、修订及待重算因子清单；不自动调用收费接口或启动因子计算。
两条渠道可能覆盖同一银行、报告期和指标，但分别保存接口原始仓库与原文证据，最终因子输入按可用时间、口径和来源规则选取，不把重复记录当成额外经济事实。

目前官方原文补充脚本主要支持已归档年度财报缺口；新季报/中报收集和新的报告类型需要核实采集器支持及原文口径后才能宣称更新完成。

### 官方年度报告采集与缺项补充

`scripts/collect_bank_original_reports.py` 从巨潮证券官方公告索引下载指定年度的完整年报，
保存证券匹配、公告索引、披露日期、原文和哈希；不调用 Token 接口，不启动因子计算。
执行前仍需检查任务锁、磁盘和研究开放日期。年度索引中的修订条目单独保留，
未发现条目不能表示已经穷尽所有更正公告。

`scripts/supplement_bank_financial_facts.py` 仅补已有时点输入中尚缺的年度指标键，
按当年列、单位、普通股/集团定义和候选值交叉核对。接口候选仅用于核验，不能据此
将原文不存在的值填入。扫描列头、编号注释或接口差异需要原文页码和哈希绑定的复核记录。
补入事实采用官方披露日末作为保守可用时间，不将下载时间冒充披露日，也不倒填次年比较列。
涉及历史缺口时，补缺检查日应为缺口发生时点；以最新日检查可能被晚采接口键误判为已齐。

2026-10-15 本地补充了42家银行2025年度原文，结果及逐项缺口保存在
`data/bank_original_reports/20261015-080818-4d21ef/supplementation_result.json`。
新事实通过 `config/bank_factors.json` 接入后，优质策略来源签名会改变，原结果应提示待重算。
此记录属于年度历史输入补缺，不表示2026季报、中报及全部历史修订已经认证。

## 已确认的取值边界与简短指令

同口径且在决策时点可用的财务候选按既有来源优先级选取；不能将不同口径的数值当作缺项替代。
常规原文补缺对已存在的银行、报告期和指标键跳过；新公告、更正及交叉核验另行处理和保存证据，不盲目覆盖。
指标缺失或无效时保留空值及原因，不擅自跨时点、跨定义或跨口径填充。来源直接提供的指标与依据基础数据计算的派生指标分别标明；新增补算来源须核验输入、可用时间、公式、单位及口径，并遵守既有研究授权。

在本项目内，用户可直接说“检查并补充银行财报，告诉我剩余缺项”，无需反复粘贴完整提示词。
如用户明确说“执行全部接口更新”或“重算指定因子”，按其具体授权、任务锁及既有访问限制执行。
